# Tasks: Session Resume After a Server Crash

**Input**: Design documents from `/specs/004-session-resume/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, quickstart.md, contracts/config-files.md

**Tests**: none requested; there is no automated test harness for game code. Validation
is the quickstart, run by the operator on a dedicated server. Three runs are gates, not
checks: Scenario 0 (fresh versus resume, engine records only) before any lobby record
is written, Scenario 2 (the airborne pin) before the rest of the hold is built, and
Scenario 7 (faults) before the feature is called done.

**Organization**: Tasks are grouped by user story. Paths are relative to the repository
root; all scripts live under `Lite Lobby/scripts/game/`. "Operator" tasks are steps only
the operator can perform (Workbench, server configuration, live runs); the agent hands
over the exact values and waits. Revised 2026-09-18 after the external design review;
the review's findings are folded into the tasks they concern; revised again 2026-09-19 after the second, third, fourth and fifth reviews (38 tasks, T010b added); the fifth review's verdict was "ready with the listed corrections", and they are in.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1 to US4)
